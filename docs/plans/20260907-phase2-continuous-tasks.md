# 第二阶段：让委托持续下去

目标：交代一次，后台执行，Mimi 核查，再按原委托继续跟进。所有自然语言仍由模型理解和选择工具，没有关键词快路径。

## 本次最小实现

1. 保留现有 Task / Session / Schedule / Outbox。新委派任务带回原对话的位置；成功结束与核查任务入队在同一 SQLite 事务内提交。后台执行器的成功只是核查触发条件，不是用户目标完成的证明。
2. Mimi 在原对话读取结果并核查文件、测试或其他证据。原委托要求继续观察才建立 Schedule；不凭空新增长期目标。失败/需要输入仍沿用已有通知及 paused/blocked 恢复机制，不切换执行器掩盖失败。
3. Schedule 保存原工作区、模型提供的有界上下文及上次结果。每轮使用独立 Session，但不丢检查进展；未结束的同一计划不会重复堆积。关闭 CLI 后 Daemon 仍能执行，重新启动后未完成记录仍保留。
4. 问“昨天那件事”时，模型优先读取 Task 和 Schedule，再按需要查询记忆；不是专门开发人际关系/项目管理系统。
5. 原始执行结果不再与核查结果重复通知。既有任务不自动追加核查；显式静默完成不唤醒核查。最多连续三轮核查，超过后总结卡点交给用户决定，避免模型无限自我委派。

## 使用变化与验证入口

- 可说：“后台整理这份资料，完成后检查引用，明天再看看有没有更新。”
- 次日可问：“昨天那份资料进展怎么样？”
- 统计入口：直接问 Mimi 最近七天的使用情况，或 `mimi daemon usage 7`。
- 统计来自现有本地持久数据，不上传新遥测；completed 仅表示执行结束，不能称为任务正确率。Token 缺采样显示未知，不当作零。
- SQLite v16 升级前保存备份，v17 新增 schedule context 和 Run 时间索引；升级后旧版程序不能直接打开 v17 数据库。回退须使用升级前备份，不能修改版本号假装兼容。

## 验证范围

`tests/continuous-tasks.test.ts` 覆盖完成与唤醒原子提交、重复完成、重启恢复、Host/Dispatcher/工具接线、上下文传承、计划去重与取消、v16 迁移、分类型统计和缺失 Token。连接异常用真实 SDK Error 类型回归；状态查询不再拉取完整历史分析，空闲轮询不再申请写锁。

本轮不是“全能贾维斯完成”：长时间睡眠/断网、模型核查质量、跨应用复杂任务仍需真实使用验证。它先补上从一次性执行走向持续委托的闭环。
